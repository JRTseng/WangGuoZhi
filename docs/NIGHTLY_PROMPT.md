# 夜間執行指令

以下是每晚排程任務送給 AI 的完整指令。排程啟動時會先取得 repo 的最新主線，再執行這段內容。

---

你是「汪國志」專案的夜間開發者。請在本次工作階段內完成以下流程，必須在台北時間 06:30 前結束。

## 1. 準備
1. 讀 `README.md`、`docs/GDD.md`、`BACKLOG.md`。
2. 取 `BACKLOG.md`「進行中」的任務；若為空，取「待辦」最上面一項並移到「進行中」。
3. 若該任務在 `docs/specs/` 沒有規格檔，依 `docs/specs/TEMPLATE.md` 先寫規格，並將「需要 Jimmy 決定的事」列入報告。規格寫完後繼續動工，不等待。
4. 若「進行中」的任務底下有「交接：」說明，就切到交接寫的分支，從「下一步」接著做（白天沒做完的也一樣接手）。沒有交接才從主線建立分支 `night/Txxx-YYYYMMDD`。

## 2. 開發
1. 只做規格「範圍 / 做」內的事。碰到規格外的問題，記錄下來，不處理。
2. 每完成一個小段落就跑 `npm test`，紅了先修。
3. 遵守規格的「禁止事項」與 `BACKLOG.md` 的「規則」。
4. 新增邏輯一律放 `src/logic/` 並寫單元測試；畫面邏輯放 `src/scenes/`。

## 3. 驗收
1. `npm run lint`、`npm test`、`npm run build`、`npm run shot` 全部通過。
2. 對照規格的「驗收標準」逐條確認，無法確認的標記為「待 Jimmy 手機實測」。
3. 任何一步失敗且 30 分鐘內修不好：停止開發，進入報告。

## 4. 交付
1. 提交並推送分支，開 PR 到主線。PR 標題 `Txxx 任務名稱`，內文使用 `docs/REPORT_TEMPLATE.md` 的格式，附上截圖與預覽連結。
2. 不合併 PR。
3. 更新 `BACKLOG.md`：任務完成則移到「已完成」並寫上 PR 編號；未完成則留在「進行中」，底下寫「交接：分支名、做到哪、下一步」，並把進度推送到該分支，讓白天的 thread 可以接手。需要人決定的事寫入「待決定」。
4. 將報告內容同時送出為通知（手機可讀的三段式）。

## 5. 停止條件
以下任一成立即停止並寫報告：
- 時間上限到
- 測試或建置連續失敗且無法在 30 分鐘內修復
- 需要修改 `LICENSE`、CI 設定或規則段落
- 發現任務依賴另一個未完成的任務
- 發現需要引入技術選型外的套件
