# T006 存檔與讀檔

## 目標
關掉瀏覽器或重新整理後，進度都還在：狗狗的等級與特訓、資源、通關進度、體力與每日次數、自動出征、主頁角色與背景、設定。

## 範圍
做：
- 整份 `GameState` 存進 localStorage（鍵 `wgz-save`），每次狀態有變就存，開遊戲時讀回來。
- 存檔帶版本號（`SAVE_VERSION`，目前 1）與存檔時間。
- 壞檔自動重置成新遊戲，壞掉的內容先搬到 `wgz-save-broken` 備份，主頁提示一次「存檔讀不出來，已重新開始」。
- 讀得懂但缺欄位或數值不合理的存檔：只修那個欄位，其他進度留著。之後的任務加新欄位，舊存檔不用特別處理。
- 設定面板最下面加「重新開始」，要連按兩次才會清除存檔。
- 離線的時間照算：讀檔後體力依經過的時間恢復、每日次數依日期重置、自動出征補算。

不做：
- 雲端存檔、帳號綁定、匯出／匯入存檔。
- 多個存檔欄位。
- 同時開兩個分頁的同步（後存的蓋掉先存的）。

## 驗收標準
- [x] 新遊戲與玩過的狀態，存了再讀完全一樣（單元測試）
- [x] 不是 JSON、不是物件、沒有 state、沒有版本號的存檔會重置成新遊戲，不會讓遊戲開不起來
- [x] 缺欄位、型別不對、超出範圍、認不得的狗狗與關卡 id 會被修正或丟掉
- [x] 存檔時間比現在晚（系統時間被調過）時從現在重新起算，不會多拿體力
- [x] 瀏覽器實測：打一關、特訓、改設定後重新整理，資源、體力、等級、特訓次數、通關進度、今天的出征次數、設定都還在
- [x] 「重新開始」按一次只提醒，做別的事會取消，連按兩次才清除
- [x] localStorage 不能用時遊戲照常跑
- [x] 所有新增邏輯有單元測試，`npm test` 全綠
- [x] 相關畫面有 Playwright 截圖，附在 PR
- [x] 手機直式瀏覽器可正常顯示

## 設計說明
- `src/logic/save.ts`：純函式。`serialize` 把狀態包成 `{ version, savedAt, state }`；`deserialize` 讀回來並回報 `new`／`ok`／`reset`；`sanitizeState` 逐欄檢查，缺的補新遊戲預設值。
- `src/state/store.ts`：唯一碰 localStorage 的地方。模組載入時讀檔，`setState` 與 `tick` 有變就存。體力滿的時候 `tick` 只會推進「上次結算時間」，這種變化不寫入，免得主頁每 0.25 秒存一次。
- 版本升級：欄位改名或改結構時把 `SAVE_VERSION` 加 1，在 `save.ts` 的 `MIGRATIONS` 加一步轉換。只是加欄位不用動版本。
- 比目前版本新的存檔（例如手機還開著舊版網頁）也盡量讀，不清掉進度。
- 測試模式（`?fast=1`）與正式模式共用同一份存檔。
- 出征紀錄只用來重播與顯示，有一筆不對就丟那一筆，不影響進度。
