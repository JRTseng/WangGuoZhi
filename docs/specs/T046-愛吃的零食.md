# T046 愛吃的零食

## 目標
每個角色有一種愛吃的零食，送對了好感度加倍。一開始不知道是哪一種，要送送看；送對一次就記下來。讓「我的家」送零食多一點猜的樂趣，也讓每個角色多一點自己的個性。

待辦只剩要等 Jimmy 填項目的 T009，所以夜間先做這一項（T044 的待決定 C：「要不要讓每個角色有愛吃的零食（送對了加倍）」，照建議先做起來）。

## 範圍
做：
- 100 個角色各有一種愛吃的零食（小肉乾／香烤肉排／大骨頭），固定不變
- 在「我的家」送到愛吃的：好感度 ×2（小肉乾 +10、香烤肉排 +24、大骨頭 +60），頭上冒「♥♥ 愛吃！」，說的話也不一樣
- 第一次送對：畫面上方跳「發現了！○○愛吃□□，以後送這個好感度加倍」，從此記著
- 記著以後：互動卡第二行寫「愛吃□□」，那顆零食按鈕寫「♥ 愛吃 好感 +N」；還不知道的時候寫「愛吃的是？」，三顆按鈕都只寫原本的數字
- 角色資料視窗「小故事」那一頁多一行「愛吃」：知道了寫零食名字，還不知道寫「？？？（到『我的家』送零食試試）」
- 存檔 `bond` 多一個 `faves`（已經知道愛吃什麼的角色），不會換日清掉；舊存檔讀進來是空的

不做：
- 討厭的零食、送錯扣好感度
- 新的零食或禮物種類
- 訓練場餵零食加經驗跟愛吃連動（經驗照舊）
- 一天三次的上限、摸摸、升級禮物的數字

## 設計說明
- 規則都在 `src/logic/bond.ts`：`favoriteSnack(dogId)`（照角色 id 算出來，不用另外填一百筆資料；現在是小肉乾 29、香烤肉排 41、大骨頭 30）、`FAVE_MULT`、`giftGain`、`knowsFavorite`、`faveText`；`giftSnack` 多回傳 `fave`（這次是不是愛吃的）與 `found`（是不是第一次送對）
- `bondView` 多一個 `fave`：玩家知道了才有值，畫面只看這個，不會提早洩漏
- 想指定某個角色愛吃什麼：在 `favoriteSnack` 前面加一張指定表即可
- 資料視窗那一頁變五行，行距從 30 縮成 25，好感度那行換行也不會碰到按鈕
- 測試狀態：`window.__WGZ__.home.card.fave`、`card.gifts[].gain`／`known`
- 存檔結構只多一個欄位，`SAVE_VERSION` 不變
