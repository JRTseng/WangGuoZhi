# T008 手機畫面調整與觸控優化

## 目標
用手機玩的時候畫面清楚、按鈕好按、不會被瀏海蓋到，也不會因為長按或雙擊跳出瀏覽器的東西。

## 範圍
做：
- 畫面照手機的實體像素畫（原本照 844 x 390 畫再放大，字和線條都糊）
- 太小的按鈕把可點範圍補到至少 44、太小的字放大到 12
- 遊戲畫面避開瀏海、圓角與底部橫條
- 擋掉長按選字／選單、雙擊與兩指放大、下拉重新整理
- 設定面板加「全螢幕」按鈕（瀏覽器支援才出現）

不做：
- PWA、加到主畫面、離線（T012）
- 直式版面（遊戲固定橫向）
- 重排各畫面的版面（只補可點範圍與設定面板的列高）

## 驗收標準
- [x] 手機上文字與圖形是清楚的：畫布大小 = 844 x 390 x 解析度倍數，版面座標不變
- [x] 各畫面可點的東西，可點範圍都不小於 44（設定面板六個開關緊貼著排，一列 35）
- [x] 畫質切到「低」用 1 倍、「中」最多 2 倍、「高」最多 3 倍，切換後設定面板還開著
- [x] 高解析度下點按、拖曳換位、捲動都照常
- [x] 所有新增邏輯有單元測試，`npm test` 全綠
- [x] 相關畫面有 Playwright 截圖（`tests/e2e/mobile.spec.ts`）
- [ ] 待 Jimmy 手機實測：清晰度、順不順、瀏海有沒有蓋到、全螢幕按鈕

## 設計說明
- **解析度倍數**（`src/logic/resolution.ts`）：倍數 = 螢幕像素比 x 畫面實際被縮放的比例，取 0.5 的倍數，
  最少 1 倍，上限跟著畫質（低 1／中 2／高 3）。畫布開成 844 x 390 x 倍數，每個場景的鏡頭放大同樣倍數
  （`src/scenes/ui.ts` 的 `fitCamera`，由 `src/main.ts` 在場景開始時呼叫），所以各畫面的版面座標完全不用改。
- **文字**：`add.text` 在 `src/main.ts` 換成照目前倍數畫的版本，所有文字自動變清楚。
- **背景**：烤成圖的背景最多照 2 倍烤（`bakeScaleFor`），再高很吃記憶體。
- **指標座標**：鏡頭放大後 `pointer.x／y` 是畫布像素，不是版面座標。場景裡要拿版面座標一律用
  `pointer.worldX／worldY`（捲動、拖曳、接飛盤都已改）。之後寫新的拖曳或捲動請照這個做。
- **畫質切換**：`applyRenderScale` 換畫布大小後主頁整個重開、設定面板接著開（文字是照建立當下的倍數畫的）。
- **自動化測試**固定 1 倍（測試機沒有顯示卡，畫大張很慢）；網址 `?res=2` 指定倍數、`?res=auto` 照實際算。
- **可點範圍**：`makeTapArea` 預設把可點範圍以中心補到 44（`MIN_TAP`，`src/logic/layout.ts`）；
  緊貼著排的列表傳 0。資源列原本只有「＋」那個小字能點，改成整條都能點。
- **安全範圍**：`index.html` 的 `#frame` 用 `env(safe-area-inset-*)` 內縮，遊戲畫布放在裡面。
- **全螢幕**（`src/scenes/components/fullscreen.ts`）：用瀏覽器的 Fullscreen API，進去後試著鎖橫向。
  iPhone 的 Safari 不支援，按鈕不會出現。
